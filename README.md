# LIAR EYE｜ライアーアイ

学校生活の小さな謎を、6人の発言から論理的に解き明かす推理パズルゲーム。

**公開ページ:** https://tt-sensei.github.io/LIAR-EYE/

## ゲームのコンセプト

「かぎを持っているのは？」「ボールを片付けたのは？」など、学校で起こりそうな身近な出来事が問題になる。

登場人物の証言を比べ、だれが答えにあたる人物なのかを論理的に考える。正解すると、答えにたどり着くための解説に加え、その人物がなぜ真相を隠していたのかという物語上の理由も読める。

うそをつく理由は、サプライズを守る、友だちをかばう、親切に気づかれるのが照れくさいなど、学校生活になじむ内容を中心にする。理由やキャラクターの印象から答えを当てるゲームではなく、**答えは必ず証言の論理から一つに決まる**ことを大切にする。

## ゲームのルール

- 登場人物は、ナビキャラサイトの6人（りく・そら・かい・さく・つき・なみ）。
- 各問題には、ある理由から真相を隠している人物が一人いる。その人物だけがうそをつき、ほかの人物は本当のことを言う。
- 発言を照らし合わせ、条件に合う人物を一人選ぶ。
- 答えを選ぶと、正解と論理的な解説、うそをついた理由が表示される。
- ヒントを使って考え方を確認できる。手書きメモ欄は、タブレットで指やタッチペンを使って推理を書き込むためのもの。
- 問題一覧では難易度でしぼりこめる。

## 問題構成

全30問。問題は、登場人物の人数や証言を組み合わせる難しさに応じて3段階に分けている。

- **LEVEL 1 — OBSERVATION:** 少ない人数の発言を読み、手がかりを見つける。
- **LEVEL 2 — CONNECTION:** 複数の証言をつなげて考える。
- **LEVEL 3 — DEDUCTION:** より多くの人物の証言を組み合わせ、候補を検証する。

問題のテーマは、かぎ、教室の片付け、配り物、図書室、花だんなどの学校生活。事件や犯罪を中心にした内容ではなく、身近な「小さな謎」を扱う。

## ファイル構成

- `index.html`：画面の土台、遊び方とルールの表示
- `style.css`：デザイン・レイアウト
- `script.js`：ゲームの動作、回答判定、ヒント・解説・うその理由の表示
- `cases.js`：全30問のデータ。問題を追加・修正するときに編集する
- `liar-eye-check.js`：問題データの整合性を検証するNode.jsスクリプト

`index.html` では、問題データの `cases.js` をゲーム本体の `script.js` より先に読み込む。問題データと表示・判定の処理を分離している。

## キャラクター対応

| 記号 | キャラクター | 画像ID |
| --- | --- | --- |
| A | りく | `riku` |
| B | そら | `sora` |
| C | かい | `kai` |
| D | さく | `saku` |
| E | つき | `tsuki` |
| F | なみ | `nami` |

A〜Fの対応は固定。問題データ、正解判定、解説、画像の対応がずれないようにする。

## 問題データの考え方

各問題には、タイトル、導入、場面、質問、ヒント、証言、論理的な解説、うその理由などを持たせる。証言のデータと画面に表示するセリフは、必ず一致させること。

内部の `statements.kind` は、現在の判定方式を表す `culprit` / `notCulprit` / `outside` / `inside` を使用している。これは実装上の名前であり、画面上では犯罪や犯人という表現を避け、「答え」「真相を隠している人」などと表現する。

うその理由は物語を豊かにするための要素であり、正解を決める論理条件には使わない。理由がなくても、証言だけから答えが一人に決まる必要がある。また、理由がその問題の行動や場面と矛盾しないかを必ず確認する。

## 品質チェック

問題を追加・修正したら、次の項目を確認する。

1. 条件を満たす答えがちょうど一人だけいる。
2. 答えになる人物の発言だけがうそになり、ほかの人物の発言はすべて本当になる。
3. 画面に表示するセリフと、判定に使う証言データが一致している。
4. ヒントは答えを直接明かさず、考え方を促している。
5. 論理的な解説が、証言と答えのつながりを説明している。
6. うその理由が、答えの人物・問題の行動・場面に合っている。
7. うその理由や人物の印象を推測しなくても、論理だけで答えが導ける。
8. キャラクター名・記号・画像IDの対応が正しい。
9. 問題文が自然で、子どもを責めたり、悪者扱いしたりする内容に偏っていない。
10. ふりがな、スマートフォン・タブレットでの表示、ヒントや答え合わせの操作が正しく動く。

### 検証スクリプト

Node.jsが使える環境で、リポジトリのルートから次を実行する。

```bash
node liar-eye-check.js
```

問題の一意解、証言データ、必須項目などを確認する。問題を追加したときは、検証結果だけでなく、実際に画面で問題を解き、文章の自然さと解説の納得感も確認する。

## 技術メモ

- 静的なHTML・CSS・JavaScriptで動作。サーバー側のPHPは使用しない。
- Kuroshiro + KuromojiをCDNから読み込み、漢字にふりがなを付ける。
- CDNや辞書を読み込めない場合も、問題本文は表示される設計を目指す。
- スマートフォン・タブレットでの操作を想定したレイアウト。
- キャラクター画像はナビキャラサイトの画像を参照する。
